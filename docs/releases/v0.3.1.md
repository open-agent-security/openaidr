# 0.3.1 — session titles

A session now carries the name its client gave it, instead of leaving the
initiating prompt to stand in for one.

## Highlights

- **`Session.title`** carries the client's own name for a session — the only
  label chosen to identify it, written by the person or by the agent, and what
  the client itself shows wherever it lists sessions. Read from Claude Code's
  `custom-title` records; the client rewrites that record on every rename, so
  the last one in the transcript is the current name.
- **The initiating prompt was a poor stand-in.** Measured on a 76-session
  corpus: the orchestrator opened with the word "hello" and its 75 sub-agents
  all opened with the same harness template, so the prompt told no two sessions
  apart in either direction. Exactly one of those sessions had a title.
- **Absent, empty and named are three different things.** `None` where the
  client never named the session — most sub-agent transcripts hold no such
  record at all — and `""` where it was deliberately renamed to nothing. The
  field is never defaulted to a substitute, so a consumer can tell the two
  apart.

## Install

`uv tool install openaidr==0.3.1` or `pip install openaidr==0.3.1`.

## Compatibility

Additive. `Session.title` is optional and defaults to `None`, and it is
appended after every pre-existing field rather than placed beside the related
ones, so a consumer constructing a `Session` positionally does not have its
later arguments shift. Span identity, the `collect` and `IncrementalCollector`
APIs, every other model field, and CLI output are unchanged.

`title` is **local-only**, on the same terms as the initiating prompt: it is
free text either way and can name a customer, a ticket or a host as readily as
a feature. A local surface may render it; nothing a finding carries may.

OpenAIDR remains beta. There is no backward-compatibility guarantee before
1.0.
