# 0.8.0 — Cursor sessions

OpenAIDR now reads a fourth agent kind, `cursor`. It reads the Cursor CLI's
chat stores, with tokens, the entrypoint and MCP connection failures from the
CLI's debug log. The design is `docs/specs/cursor.md`, with ADR-0037 and
ADR-0038.

## Highlights

- **Cursor CLI sessions are read.** Each conversation under
  `~/.cursor/chats/` is a session, a sub-agent's included. Every tool call has
  its arguments, its result, a status from Cursor's own typed outcome, a refusal
  kind, an exit code and a duration. Calls are classed for both model families'
  tool names.
- **Cursor usage comes from its debug log.** Cursor writes no usage to its
  store. The reader takes one response for each usage line, with input apart
  from cache reads and writes. Where the CLI writes no usage line, as the
  standard CLI does, a turn's totals from its outcome line are one response.
  The standard CLI's terminal UI writes neither.
- **Client errors are turns.** A turn that ended in an error is a turn with
  role `error`, with Cursor's own words from the transcript.
- **Who is signed in.** `signed_in("cursor")` reads `authInfo` from
  `cli-config.json`.

## Install

`uv tool install openaidr==0.8.0` or `pip install openaidr==0.8.0`.

## Compatibility

Beta, no back-compat guarantee before 1.0.

- **A new kind appears.** `default_readers()` and `IncrementalCollector` now
  include `cursor`. `IncrementalCollector.locations()` names three Cursor
  directories, the debug log directory under the OS temporary directory among
  them. A consumer that lists every kind sees one more.
- **New keyword.** `default_readers(cursor_root=…)`, and `OPENAIDR_CURSOR_ROOT`
  for the CLI.
- **Not read.** The Cursor desktop app's own chats and Cloud agents.
- No span derivation for an existing kind changed. `adr-sensor` is unchanged.
