# 0.6.3 — a long-lived reader's memory stays bounded

A long-running consumer, such as a daemon that keeps one `IncrementalCollector`
open for days, kept the Claude Code projection of every transcript it had ever
read, including each sub-agent's file, even after the file was deleted. Its
memory grew with the number of transcripts it had seen. This release bounds
that cache.

## Highlights

- **The incremental Claude Code reader keeps a bounded cache.** It keeps
  projections for at most the 128 most recently used transcripts and 16 MiB of
  source bytes, counting incomplete trailing records. The file just read is
  never evicted by this budget, so a live transcript larger than 16 MiB on its
  own stays cached and is not reprojected from byte zero on every call. An
  evicted file is read again from the start the next time it is asked for,
  with the same full result and the same span identities (ADR-0029, which
  supersedes ADR-0011).
- **Devin skill listings name their skills.** The system message in which a
  Devin session lists its skills is now a `skill_listing` context item, with
  one part per skill, in place of an unnamed `system` item. Each skill comes
  from the message's `agent-ext/skills-loaded` extension, paired in order with
  its `- **name**:` entry. A listing whose names and entries do not pair one
  for one keeps the source and gets no parts (ADR-0016).

## Install

`uv tool install openaidr==0.6.3` or `pip install openaidr==0.6.3`.

## Compatibility

Beta, no back-compat guarantee before 1.0.

- **Devin context items.** A Devin skill listing that 0.6.2 reported with
  source `system` now reports `skill_listing` and carries parts. A consumer
  that counted Devin `system` items will see one fewer per session that lists
  skills.
- **Re-reads after eviction.** A consumer with more than 128 transcripts, or
  more than 16 MiB of them, in active use pays a full read of an evicted
  transcript the next time it is collected. The result is the same either
  way.
- No span derivation, kind, class or session field changed. `ContextItem.source`
  documentation now lists only the values the readers emit. `adr-sensor` is
  unchanged.
