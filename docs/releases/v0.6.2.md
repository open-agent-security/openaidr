# 0.6.2 — a cloud session's own account

A Claude Code cloud session runs in a container that several people can start
sessions in from one environment. Its configuration file belongs to the
environment and can record whoever set it up, so reading `oauthAccount` alone
could name the wrong person. This release reads the account the session
itself states.

## Highlights

- **A Claude Code cloud session is signed in as the account it names.** With
  `CLAUDE_CODE_REMOTE=true` and a non-blank `CLAUDE_CODE_ACCOUNT_UUID` in this
  package's environment, `signed_in("claude-code")` returns that account, and
  `CLAUDE_CODE_USER_EMAIL` as its email (None when blank or unset). The
  configuration file adds its `displayName` and `billingType` only when it
  records the same account, and never fills in a missing email. Everywhere
  else ADR-0027 stands: the file decides, as on a laptop (ADR-0028).

## Install

`uv tool install openaidr==0.6.2` or `pip install openaidr==0.6.2`.

## Compatibility

**Additive, for cloud sessions only.** Inside a Claude Code cloud session,
`signed_in("claude-code")` can now return a different account than the
configuration file names, with no name or plan when the file is someone
else's. Outside one, nothing changed. `sign_in_records` is unchanged. No span
derivation, kind, class or session field changed.

Beta, and no back-compatibility guarantee before 1.0. Supported hosts are
macOS and Linux.
