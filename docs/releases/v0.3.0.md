# 0.3.0 — incremental collection for growing sessions

Long-lived consumers can now analyze active Claude Code sessions without
re-projecting the entire transcript after every append.

## Highlights

- **`IncrementalCollector`** accepts an agent kind and one transcript path. Its
  first read is cold; later reads project only newly appended records while
  returning the current full `Session` model.
- **Partial writes stay invisible.** A trailing JSONL record contributes
  nothing until its terminating newline arrives, including a tool result that
  would otherwise make a pending call look resolved too early.
- **Recovery is explicit.** An inode replacement or observed truncation resets
  that file to byte zero. Cursor state is in memory only, so process restart is
  also a deliberate cold read.
- **MCP connection logs are read incrementally too.** An MCP-log-only append —
  a tool result landing after the transcript went quiet — is visible on the
  next incremental collection without rereading old bytes. The reader keeps
  one in-memory byte cursor and complete-line cache per connection-log file,
  admits only newline-terminated records, and rebuilds a fresh `MCPLogIndex`
  from the cached lines, so ordering, incompleteness and sealing semantics are
  the cold reader's. An inode change or observed truncation resets that file;
  a file that disappears leaves the cache.
- **Cold collection is unchanged.** The windowed `collect` API remains the
  stateless, complete path for one-shot consumers.

## Performance

Before this release, collecting a synthetic 10,000-call Claude Code transcript
took about 9.6 seconds, while correlation and deterministic analysis over the
result took about 0.04 seconds. The parsing dependency's whole-file projection
was the dominant cost. The incremental path retains that projection and invokes
the per-record projector only for appended complete records.

Recovery of fields omitted by the parsing dependency and construction of the
immutable full-session return value still scale with session size. This release
removes the measured dominant cost; it does not claim constant work for an
arbitrarily large session.

## Install

`uv tool install openaidr==0.3.0` or `pip install openaidr==0.3.0`.

## Compatibility

The new API is additive. Existing readers, the `collect` function, the session
model, span identities, and CLI output are unchanged. `IncrementalCollector`
must be kept alive across calls to retain its cursors; constructing one per
filesystem event falls back to a cold first read each time.

The Claude Code incremental reader uses a private per-record method from the
exactly pinned `adr-sensor` release. Contract tests compare incremental and cold
results, including structurally identical tool calls, so a dependency change
that moves those semantics fails before release.

OpenAIDR remains beta. There is no backward-compatibility guarantee before
1.0.

## Decisions

- [ADR-0011](../adrs/0011-keep-append-cursors-in-memory.md) — keeps append
  cursors in memory, commits only newline-terminated records, and records why
  the return value remains a full session rather than a turn delta.
- [ADR-0012](../adrs/0012-keep-mcp-log-append-cursors-in-memory.md) — extends
  the same rules to the MCP connection logs, and records why each pass rebuilds
  a fresh index from cached lines rather than mutating a sealed snapshot.
