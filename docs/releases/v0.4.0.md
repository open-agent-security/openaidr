# 0.4.0 — what each request to the provider consumed

A session now carries a record of every request it made to its model provider,
with the tokens the transcript recorded for it. Workflow agents are read as
the sub-agents they are. Compactions carry their time, and the client's
generated title is read; its own running totals are not.
`docs/specs/token-usage.md` is the design.

## Highlights

- **One record per provider response** (ADR-0014). `Session.responses` holds
  a `ModelResponse` per `message.id`.
  - Each carries tokens by price-relevant bucket (`TokenUsage`): uncached input,
    cache reads, cache writes split by lifetime, output, reasoning, and web
    search and fetch requests.
  - It also carries the model, tier, speed and region the record states, and
    its time.
  - Claude Code writes one response as several records. Every field is read
    from the last of them, never merged, so summing per record (about 2.1×) is
    no longer possible.
- **`final` says whether a count is complete.** A response is final when its
  last record has a stop reason.
  - Every main-session response ends in one. 65–70% of sub-agent responses
    never do, and their output is a lower bound.
  - Nothing on disk states the true figure, and this package does not
    estimate it.
- **Turns name their response.** `Turn.response_id` joins a turn to the
  response it belongs to; several turns can share one.
- **The client's own running totals are not read** (ADR-0015). Claude Code's
  `cost-state` records are recognised and skipped: they carry no time, are
  written after the work, and add about half a percent to the tokens the
  transcripts record. This package still prices nothing.
- **`Session.generated_title`** is the client's generated name, from its
  `ai-title` records. It is local-only, like `title`, and withheld from
  `render_json`.
- **`Compaction.occurred_at`** is the boundary record's own time.

## Fixed

- **Workflow agents are sub-agents.** Files at
  `<sessionId>/subagents/workflows/<run>/agent-<id>.jsonl` were read as main
  sessions under the parent's identity.
  - A cold pass reported 22 sessions with one id, and could keep an agent
    while dropping the parent.
  - The parent's MCP enrichment was withheld as a collision.
  - `collect_file` on an agent returned the parent's identity.
  - Each is now `claude-code:<parent>:agent-<id>`, with sidechain turns, by
    ADR-0001's existing rule.
  - Other files under `subagents/`, such as a run's `journal.jsonl`, are not
    read.

## Install

`uv tool install openaidr==0.4.0` or `pip install openaidr==0.4.0`.

## Compatibility

**Additive for the model.** The new types, and fields appended after every
existing defaulted field on `Turn`, `Session` and `Compaction`, leave anything
that constructs them positionally working. Span identity, turn identity and
every existing field are unchanged. `render_json` gains `responses` and each
turn's `response_id`.

- **A workflow agent is no longer reported under its parent's identity.** A
  consumer that stored such a session under the parent's id will now see a
  separate sub-agent session, and the parent's own turns and MCP enrichment.
- **A response is an update key.** A consumer that stores responses replaces
  by `(session, response_id)` as a file grows, never appends: a later read
  can raise output and turn `final` true.

Beta, and no back-compatibility guarantee before 1.0. Supported hosts are
macOS and Linux.
