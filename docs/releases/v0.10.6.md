# 0.10.6 — File edits carry what they removed

A file edit's canonical arguments now say what it removed as well as what it
added, for every agent kind whose argument keys are confirmed, so a consumer
never has to parse an agent's own edit format.

## Highlights

- **Canonical `edits` for every file edit.** A `file_edit` call gives `edits`,
  one `{path, kind, old_text, new_text}` entry per hunk or file: Claude Code
  `Edit` and `MultiEdit` (one entry per hunk), Codex and Cursor patches (the
  `-` lines as `old_text`), Cursor `StrReplace` and Devin `edit`. Codex's
  recorded `changes` also give a deleted file's content. The values come only
  from the call's own arguments (ADR-0042). Where they do not hold the removed
  text, `old_text` is absent: Claude Code `NotebookEdit`, a file a patch
  deletes, Cursor `EditNotebook`, and Devin `apply_patch` and `notebook_edit`.
  `docs/specs/session-collection.md` defines the key and lists each gap.

## Install

`uv tool install openaidr==0.10.6` or `pip install openaidr==0.10.6`.

## Compatibility

Beta, no back-compat guarantee before 1.0.

- **Additive only.** `edits` and `old_text` are new keys in
  `canonical_arguments`. The existing `path`, `new_text` and the existing
  `edits` entries' `path`, `kind` and `new_text` are unchanged. A Claude Code
  `MultiEdit` also gains a top-level `new_text`, its hunks' added text joined
  with newlines.
- **No span-identity change.** Session IDs, span IDs, agent kinds, the
  `(server, tool)` split and the `Session` fields are the same as in 0.10.5.
- **Dependencies are unchanged.**
