# 0.0.1 — name claim and publish path

## Highlights

- **Claims `openaidr` on PyPI and ships the `openaidr` executable.** Installing
  the package makes the command available; it reports its version and otherwise
  exits non-zero saying session collection is not implemented yet. This release
  exists to make the name resolvable, not to be useful.
- **Consumers can depend on `openaidr` by version instead of by path.** Until
  now the package had never been published, so the only thing that resolved was
  a local checkout — which no CI runner has. A downstream repo pinning
  `openaidr>=0.0.1` can now `uv sync --frozen` on a clean runner.
- **Publishes via Trusted Publishing.** Tags matching `v*` on main trigger
  `publish-pypi.yml`, which gates on both version strings agreeing with the tag
  and on a committed release-notes file before it uploads. No PyPI token exists
  in the repo.
- **Depends on `adr-sensor==1.0.0`** ([Uber's ADR project](https://github.com/uber/ADR),
  Apache-2.0), the session parser the collection work sits behind. Nothing in
  this release exercises it yet.

## Install

`uv tool install openaidr==0.0.1` or `pip install openaidr==0.0.1`.

## Compatibility

Pre-alpha, and deliberately empty. There is no session model, no reader and no
CLI surface beyond `--version` — `openaidr` with no arguments prints a
not-implemented notice and exits 1. Nothing here is a contract; the session
model and its span identity arrive in a later release, and that is the first
version worth writing a consumer against.
