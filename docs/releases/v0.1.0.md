# 0.1.0 — Claude Code sessions, with MCP enrichment

## Highlights

- **`openaidr sessions` prints what each agent on this machine actually did.**
  Sessions, turns, tool calls and how each one ended, over a bounded window:
  `--since` sets the window, `--agent-kind` selects a kind, `--detail` lists
  every session and call rather than the summary alone, and `--format json`
  emits the same account machine-readably. Per-call timings come from the
  transcript's own record of both ends of a call — the parsing dependency's
  event schema carries no timestamp below the session.

- **The session model, and the span identity a consumer addresses rows by.**
  Three nested levels — session, turn, tool call — with `span_id` derived from
  the session, the turn's own stable key, and the call's index *within that
  turn*. Appending later turns cannot move it and a skipped record cannot shift
  it, so a consumer that drew a call on one pass can attach outcome and
  enrichments to the same row on the next (ADR-0001). Six outcome statuses;
  `unknown` means the call ran and the evidence does not say whether it
  succeeded, which is not the same as `ok`.

- **A Claude Code reader of our own over the JSONL transcripts.** Discovery is
  per-file rather than a whole-tree pass keyed on `sessionId`, which is what
  keeps a subagent distinct from its parent. It emits five of the six statuses
  (`ok`, `error`, `rejected`, `pending`, `unknown`) — `rejected` inferred from
  the refusal wording that survives in the result body, `pending` from a missing
  result. `interrupted` is modelled but not emitted, because no source records
  it.

- **MCP connection logs supply transport, server identity and call outcome.**
  Claude Code's per-server logs are the only place those are written down, so
  the reader joins them onto the calls it already has, along with durations
  (ADR-0003, ADR-0005). The enrichment is best-effort — the path is an
  undocumented cache — and `mcp_log_state` says which case a session is in
  rather than letting an absence read as a negative.

- **Evidence gaps are reported, never quietly filled.** Enrichment is withheld
  wherever the join cannot be trusted: an ambiguous session id, an overlapping
  or structurally mismatched reused id, a subagent, an incomplete server log
  (ADR-0002, ADR-0006). Recovery keys are scoped to the identity that makes them
  unique (ADR-0004), evidence precedence is one rule rather than one per merge
  site (ADR-0007), claimants outlive the window that filtered them (ADR-0008),
  and a single match is only trusted after a complete discovery pass (ADR-0009).
  Unreadable roots, dangling symlinks, non-directory roots and subtrees `glob()`
  silently drops are all surfaced as failures.

- **`(server, tool)` splitting is per agent kind, never global.** Applied to the
  wrong kind, a general pattern does not fail to find a server — it finds the
  wrong one, which then resolves to the wrong component downstream.

- **`adr-sensor` is pinned exactly at `1.0.0`**, up from `>=1.0.0`
  ([Uber's ADR project](https://github.com/uber/ADR), Apache-2.0). It has a
  single published release and it truncates long tool arguments and results
  before OpenAIDR sees them; both properties shape the design, so the version is
  fixed rather than floated.

## Install

`uv tool install openaidr==0.1.0` or `pip install openaidr==0.1.0`.

## Compatibility

The contract begins here. 0.0.1 shipped no session model, no reader and no CLI
beyond `--version`, so nothing in this release changes behaviour an existing
consumer could have depended on. Span identity, the model's field set and the
per-kind normalisation rules are documented in
[`docs/specs/session-collection.md`](../specs/session-collection.md); that
document, not this package's internals, is what a consumer writes against.

**One agent kind: `claude-code`.** `adr-sensor` parses seven, this package
instantiates one. Reading a kind needs two things that are ours — a reader and a
row in `AGENT_KIND_BY_SOURCE` — and neither exists for any other kind. A Codex
or Cursor session on the same machine is absent from the output entirely, not
collected and marked. Codex and Cursor are the intended next kinds.

Fields named in `LOCAL_ONLY` — prompt and turn text, arguments, results, error
text, working directory, machine, user, context items, MCP failure detail — are
for correlation and local rendering. They are not part of what travels to a
consumer's finding.

Pre-alpha, no back-compat hedging. One cold pass, held in memory.
