# 0.1.1 — attribution that ships, and a way in for contributors

No runtime code changed in this release. `src/` is byte-identical to 0.1.0:
the session model, span identity and the per-kind normalisation rules are
untouched. What changed is what the distribution carries and what the project
tells someone who does not already work on it.

## Highlights

- **The `NOTICE` now ships inside the wheel and the sdist.** It did not in
  0.1.0. Hatchling collects `LICENSE*` through `license-files`, the file was
  named `NOTICE.md`, and nothing else referenced it — so every installed copy
  of 0.1.0 carries no attribution for `adr-sensor` at all, which Apache-2.0
  section 4(d) requires of a distribution that depends on it. The file is now
  `NOTICE`, declared via PEP 639 `license-files`, and both it and `LICENSE`
  land in `.dist-info/licenses/`. It also states OpenAIDR's own copyright
  beside Uber's, and records that upstream is consumed unmodified from PyPI
  rather than vendored — the fact a redistributor actually needs.

- **Marked beta.** `Development Status :: 4 - Beta`, up from `2 - Pre-Alpha`.
  Claude Code collection is complete through MCP connection-log enrichment,
  with span identity, the outcome model and the local-only boundary each
  pinned by tests. The deprecated Apache licence classifier is dropped; it is
  redundant beside the PEP 639 `License-Expression` the build already emits.

- **The local-only boundary is documented where a reader will find it.**
  `LOCAL_ONLY` decides which fields never leave the machine, and until now it
  was discoverable only by reading `model.py` or the spec. The README now
  carries the per-field table of what each surface shows versus withholds,
  together with the caveat that the boundary is the CLI's: a consumer
  embedding OpenAIDR as a library receives the full model, and
  `Session.public_descriptor()` is the deliberately narrow shape meant to
  travel outward.

- **What this package adds on top of `adr-sensor` is now stated, not implied.**
  Per-file discovery rather than upstream's whole-tree walk (which collapses a
  subagent into its parent), span identity, six outcome statuses, per-call
  timing, MCP enrichment, per-kind tool-name splitting, and reported failures
  in place of silent absences.

- **A contributor can now add an agent kind without reading the source first.**
  `CONTRIBUTING.md` walks the four wiring points — the source-name mapping, the
  tool-name split, the reader itself, and registration — then the traps, each
  pointing at the ADR that records it: identity that depends on the file path,
  span identity that must survive a growing session, recovery keys scoped to
  what makes them unique, and withholding an outcome rather than inferring
  success from a missing error.

- **A disclosure path, with the threat model spelled out.** `SECURITY.md` says
  what counts as a vulnerability in a tool whose job is reading transcripts
  without spreading them: a `LOCAL_ONLY` field reaching `--format json`, any
  network call at all, any write to a path OpenAIDR reads, or a hang on a
  hostile MCP log, since a server controls its own log lines. It also says what
  is not one — a stated gap is coverage, and coverage belongs in a public
  issue.

- **The local-only boundary is now pinned on both surfaces.** Two tests
  asserted that a prompt and a credential a server echoed back stay out of
  `--format json`; nothing asserted it of the text surface. Since `LOCAL_ONLY`
  explicitly permits a *local* surface to carry turn text, nothing but a test
  stood between a future `--detail` and printing a transcript. Both surfaces
  are covered now.

- **Repository hygiene.** The no-proprietary rule is enforced by a real check
  in CI and pre-push rather than by an assertion in `CLAUDE.md` that one
  existed; the Codex/Claude review loop no longer reaches fork pull requests;
  Dependabot and a gitleaks config are in place.

## Install

`uv tool install openaidr==0.1.1` or `pip install openaidr==0.1.1`.

## Compatibility

**Nothing to do.** No consumer-visible behaviour changed. Span identity is
derived exactly as in 0.1.0, the model's field set is unchanged, and the
`(server, tool)` split and status mapping for `claude-code` produce identical
output — spans stored against 0.1.0 remain valid, and `docs/specs/session-collection.md`
still describes the shipped behaviour without amendment.

Beta, and no back-compatibility guarantee before 1.0. One agent kind reads
(`claude-code`); Codex and Cursor are the two intended next kinds. Each run is
still one cold pass over the window, held in memory.
