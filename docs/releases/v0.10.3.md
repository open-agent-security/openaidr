# 0.10.3 — Compressed Codex rollouts are read

Codex can store a finished rollout compressed as `.jsonl.zst`. The Codex reader
now reads those files. Before, it reported each one as unreadable. A Codex
desktop follow-up no longer withholds its session.

## Highlights

- **Compressed Codex rollouts are read.** A `.jsonl.zst` rollout now gives its
  session, calls and usage, as a plain rollout does. Codex never appends to a
  compressed rollout, so each read decodes the whole file. Each read is
  bounded. A compressed rollout whose last record has no newline is a cut
  record, not a record still being written. It is now one per-file failure,
  and the session is not reported as complete
  ([Codex](../specs/codex.md#compressed-rollouts)).
- **A Codex desktop follow-up no longer withholds its session.** A follow-up
  sent with `codex_app.send_message_to_thread` has output but no invocation
  `call_id`. The reader rejected that record and withheld the whole session,
  with its later calls and usage. It now keeps the record as injected context
  and makes no invocation from it. Other malformed outputs are still rejected.

## Install

`uv tool install openaidr==0.10.3` or `pip install openaidr==0.10.3`.

## Compatibility

Beta, no back-compat guarantee before 1.0.

- **No span-identity or model change.** Session IDs, span IDs, agent kinds,
  the `(server, tool)` split and the `Session` fields are the same as in
  0.10.2.
- **More Codex sessions appear.** A consumer that showed compressed rollouts
  as unreadable, or that lost a session with a desktop follow-up, now gets
  those sessions.
- **New dependency below Python 3.14:** `zstandard==0.25.0` (BSD-3-Clause).
  It only decompresses Codex rollouts. Python 3.14 and later use the standard
  library's `compression.zstd`. `adr-sensor` is unchanged.
