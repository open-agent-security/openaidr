# 0.9.0 — Cursor desktop sessions

The `cursor` kind now reads the Cursor desktop app's agent panel. The reader
decodes the app's `state.vscdb` with the same decoder that it uses for the CLI's
chat stores. Usage comes from the app's structured log. The design is
`docs/specs/cursor.md`, with ADR-0039.

## Highlights

- **Cursor desktop conversations are read** (ADR-0039). Each conversation in
  `<user data>/User/globalStorage/state.vscdb` is a `cursor` session, and a
  sub-agent's conversation is one too. The reader opens the database
  read-only. The entrypoint is `ide`, unless an automation or a background
  agent started the conversation.
  - The user data directory is `$VSCODE_PORTABLE/user-data`, else
    `$VSCODE_APPDATA/Cursor`. Else it is `~/Library/Application Support/Cursor`
    on macOS and `$XDG_CONFIG_HOME/Cursor` on Linux.
  - Usage comes from `Cursor Structured Logs.log`. A usage line is placed
    only when one turn is open in its window.
  - A conversation that does not decode is a `ReaderFailure` on each pass, not
    only on the first pass.
  - `IncrementalCollector` rebuilds desktop sessions when the database, its
    WAL or a structured log changes.
  - Known gaps: the app writes usage only where its agent loop runs on the
    machine (C11). A turn that never ends stops usage placement in its window
    (C13).
- **An MCP call names the server that the configuration names.** The desktop
  app calls a server from `~/.cursor/mcp.json` by the identifier
  `user-<name>`. The reader reads
  `projects/<slug>/mcps/<identifier>/SERVER_METADATA.json` and gives its
  `serverName` as `mcp_server`. Without the file, the identifier stays. The
  reader applies this rule to CLI calls too.
- **Who is signed in to the desktop app.** When the CLI names no one,
  `signed_in("cursor")` gives the desktop app's sign-in: its `authId`, its
  cached email and its plan. When both name the same `authId`, the CLI's
  account gets the desktop app's plan. The reader does not read the tokens.

## Install

`uv tool install openaidr==0.9.0` or `pip install openaidr==0.9.0`.

## Compatibility

Beta, no back-compat guarantee before 1.0.

- **`mcp_server` can change for a Cursor CLI call.** If the client recorded
  the call's server in `SERVER_METADATA.json`, `mcp_server` is now the
  configured name. For example, 0.8.0 gave `user-probe` and 0.9.0 gives
  `probe`. The span does not change. A consumer that stored `mcp_server`
  from 0.8.0 gets the new value on the next read of the same span.
  `MCPConnection.server` stays the identifier, so for such a server the two
  values are now different.
- **More Cursor sessions.** The `cursor` reader now also returns the desktop
  app's conversations. A caller that passes `cursor_root=` for a fixture also
  gets the real desktop conversations of the machine. Pass
  `cursor_user_data_root=` to stop this. The `openaidr sessions` command has
  no environment variable for this root.
- **New keyword.** `default_readers(cursor_user_data_root=…)`,
  `default_incremental_readers(cursor_user_data_root=…)` and
  `CursorReader(user_data_root=…)`.
- **More watched paths.** `CursorReader.locations()` names two more
  directories: `<user data>/User/globalStorage` and `<user data>/logs`.
  `sign_in_records("cursor")` also names `state.vscdb` and
  `state.vscdb-wal`.
- **A new entrypoint value.** `Session.entrypoint` can be `ide`. Only Cursor
  desktop sessions give it.
- No span derivation changed. `adr-sensor` is unchanged, and no dependency
  changed.
