# 0.7.0 — a third agent kind: Codex

This release reads a third agent kind, `codex`. An OpenAIDR-owned reader reads
Codex's rollouts and its log database. The reader follows the design of the
Claude Code reader, because Codex also writes one append-only file per thread.
`docs/specs/codex.md` is the design.

## Highlights

- **Codex sessions are read** (ADR-0030 to ADR-0036). `codex` covers Codex CLI
  in the terminal, `codex exec`, and the IDE extension and Codex app through
  `codex app-server`. Codex Cloud tasks are not covered, because they run in
  OpenAI's containers.
  - The reader reads `sessions/**/rollout-*.jsonl` and `archived_sessions/`.
    It does not use `adr-sensor`, whose Codex parser drops `apply_patch` calls
    and marks each returned call as successful.
  - Each message and each call record is one turn. A call's span is
    `span_id(session, turn key, 0)`. The turn key comes from the record's own
    `ordinal`, so it does not change when the rollout grows.
  - A sub-agent session is `codex:<root thread>:<thread>`, by the existing
    rule in ADR-0001.
  - Statuses come from Codex's own closed vocabularies. An unknown value is
    `unknown`, never a guess (ADR-0033). A late completion is filed under the
    turn that it names (ADR-0035).
  - Token usage is one model response for each `token_usage_record`. Cached
    input is taken out of `input_tokens` (ADR-0031).
  - MCP connections come from the newest `logs_<n>.sqlite`. Each connection is
    placed by the `thread/start` request that created the thread, never by
    time (ADR-0032). `codex exec` writes no log rows, so its sessions are
    `no_log_for_session`.
  - The data root is `$CODEX_HOME`, else `~/.codex`. `OPENAIDR_CODEX_ROOT`
    overrides it for the CLI. `default_readers(codex_root=…)` does the same
    for callers.
  - Known gaps: MCP connections under `codex exec`, exit codes in older
    rollouts, skill attribution and the compaction trigger. The design lists
    each gap under Open facts.
- **A Code Mode cell is a `script` call** (ADR-0036). A Code Mode `exec` cell
  runs other tools. Codex records each of these tools as its own call, so each
  is also its own call here. The cell's status comes from its own status line.
- **`signed_in("codex")`** reads the identity claims from the `id_token` in
  Codex's `auth.json`, when Codex signs in with ChatGPT. The access token, the
  refresh token and any API key are not read into anything it returns. The
  token's signature is not checked. With an API key, or with the sign-in in
  the keyring, the answer is None. `sign_in_records("codex")` names
  `auth.json` and `config.toml`.
- **`ModelResponse.context_window`** gives the model's context window in
  tokens, where the agent records it. Codex records it for each turn. Claude
  Code and Devin give None.
- **Codex canonical arguments.** A shell call gives `command` as the script
  that the model wrote, without the `bash -lc` wrapper. An `apply_patch` call
  gives `edits`, a new canonical key. It has one `{path, kind, new_text}` for
  each file that the patch changes.

## Install

`uv tool install openaidr==0.7.0` or `pip install openaidr==0.7.0`.

## Compatibility

**Additive for the model.** `ModelResponse.context_window` has a default and
comes after each existing field. Span identity, turn identity and each
existing field are unchanged for `claude-code` and `devin`.

- **`default_readers()` and `default_incremental_readers()` now return a Codex
  reader too.** Codex's root has its own keyword, `codex_root=`. Without it,
  the reader reads Codex's default location.
  - A caller that passes a test or fixture root now also gets the real Codex
    sessions of that machine. Pass `codex_root=` to stop this.
  - A consumer that expects only `claude-code` and `devin` sessions now also
    gets `codex` sessions.
- **New values in closed vocabularies.** A consumer that handles each case
  must add these:
  - `ToolCall.tool_class` gains `script`. Only Codex gives it.
  - The canonical argument keys gain `edits`. Only Codex gives it.
  - `Turn.role` can be `error`, for a failure that the client recorded. Only
    Codex gives it.
- `adr-sensor` is unchanged.

Beta, and no back-compatibility guarantee before 1.0. Supported hosts are
macOS and Linux.
