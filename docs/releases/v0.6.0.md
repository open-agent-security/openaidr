# 0.6.0 — who an agent is signed in as

A consumer that ties work or spend to a person needs to know who each agent was
signed in as, and no transcript records it. This release reads it, for the kinds
whose sessions this package reads.

## Highlights

- **`openaidr.accounts.signed_in(kind)`** returns an `Account` (`kind`,
  `account_id`, `display_name`, `email`, `plan`) or None, with one read of the
  agent's own sign-in record (ADR-0027). It never raises.
  - `claude-code`: `oauthAccount`, in the file Claude Code itself locates. With
    `CLAUDE_CONFIG_DIR` or `config_dir` set, that is `.claude.json` inside the
    directory, else `~/.claude.json`. It is `.claude-custom-oauth.json` when
    `CLAUDE_CODE_CUSTOM_OAUTH_URL` is set, and a legacy `.config.json` wins,
    as Claude Code 2.1.283 chooses them.
  - `devin`: None. Devin keeps no person on disk.
- **`openaidr.accounts.sign_in_query("devin")`** names Devin's own `devin auth
  status` command and reads what it prints into an `Account`. This package
  never runs it, because the command calls Devin's server and sensing here is
  read-only. A consumer that chooses to ask runs it.
- **`openaidr.accounts.sign_in_records(kind)`** names every file whose change
  can change the answer, so a consumer asks again only then.
- **A Claude Code file tool's success is read from its structured result**
  (ADR-0026). `Write`, `Edit` and `Read` calls that succeeded were `unknown`,
  because Claude Code writes `is_error` only on failure. They are now `ok`,
  read from the `toolUseResult` object that states the outcome.

The answer is the agent's record of its sign-in, never a check of the
credential: the Keychain, `.credentials.json` and `credentials.toml` are never
opened. `display_name` and `email` are `LOCAL_ONLY`.

## Install

`uv tool install openaidr==0.6.0` or `pip install openaidr==0.6.0`.

## Compatibility

**Additive.** New module `openaidr.accounts` and model `Account`, and
`LOCAL_ONLY` gains `display_name` and `email`. A successful Claude Code
`Write`, `Edit` or `Read` call reads `ok` where it read `unknown`. No span
derivation, kind or session field changed.

Codex and Cursor answer None until their sessions are read.

Beta, and no back-compatibility guarantee before 1.0. Supported hosts are
macOS and Linux.
