# 0.3.2 — an unchanged MCP cache is not re-read

A long-lived collector polls the Claude Code cache over and over, and on most
passes nothing in it has moved. It still paid for a full rebuild of the MCP
connection-log index every time. This release stops paying for work that
would reproduce the previous answer exactly.

## Highlights

- **The MCP log index is reused when no log moved.** The incremental reader
  kept a byte cursor per connection log (ADR-0012) but still rebuilt the whole
  `MCPLogIndex` from every retained line on every pass. On a cache of 8,109 log
  files and 94,535 lines, that rebuild alone cost about 0.77s per pass, so a
  collector polling once a second spent most of a core re-deriving an
  identical index. When a pass finds the same files, the same discovery
  failures and no new complete line, the previous index is now returned as is.
  A log whose size equals its cursor is no longer reopened either. A warm,
  unchanged pass on the same cache drops to about 0.35s; what remains is
  walking the cache tree, which ADR-0012 already leaves out of scope.
- **An unreadable log is never mistaken for an empty one.** The skip-reopen
  shortcut applies only to a file that has been opened successfully at its
  current cursor. A zero-byte log whose first open fails keeps being retried
  and keeps being reported as unreadable, rather than reading as empty after
  one poll.
- **Native Windows support is deferred (ADR-0013).** OpenAIDR targets macOS
  and Linux hosts across the library, CLI, session discovery and incremental
  collection. A session record that names Windows paths is still read as data.

## Install

`uv tool install openaidr==0.3.2` or `pip install openaidr==0.3.2`.

## Compatibility

**Nothing to do.** Span identity, the model's field set, and the `(server,
tool)` split and status mapping for `claude-code` are unchanged, so spans
stored against 0.3.1 remain valid. `docs/specs/session-collection.md` still
describes the shipped behaviour without amendment. Dependencies are unchanged.

- **An `MCPLogIndex` may be handed out more than once.** The incremental
  reader can return the same index object on consecutive passes. OpenAIDR's own
  reader copies each outcome queue before consuming it; a consumer that reads
  an index directly should treat it as read-only too.

Beta, and no back-compatibility guarantee before 1.0. Supported hosts are
macOS and Linux.
