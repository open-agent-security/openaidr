# 0.5.2 — one Devin, and every tool it calls

Devin CLI and Devin Desktop's local agent are one agent writing one store, but
their sessions arrived as `devin-cli`, and a Devin tool newer than the tool
table arrived unclassed. This release fixes both.

## Highlights

- **The Devin kind is `devin`** (ADR-0024). Devin Desktop runs its own bundled
  copy of the same agent and writes the same `~/.local/share/devin/cli` store,
  so the kind names the agent, not one way of starting it. A main session is
  `devin:<id>` and a sub-agent `devin:<id>:<agent>`.
- **Every Devin tool gets a class** (ADR-0025). `find_file_by_name` and
  `code_search` are `file_search` and `web_search` is `web_search`, each seen
  in real sessions or the binary. A tool the table does not name takes the ACP
  kind Devin declared for the call in `tool_call_state`: `move`, `execute`
  and `fetch` map to `file_write`, `shell` and `web_fetch`, and the kinds ACP
  defines over "files or data" or information anywhere (`read`, `edit`,
  `delete`, `search`) to `other`. `toolclass.class_of_acp_kind` and
  `ACP_KIND_CLASSES` are public.

## Install

`uv tool install openaidr==0.5.2` or `pip install openaidr==0.5.2`.

## Compatibility

**Breaking for Devin.** `agent_kind` is `devin` where it was `devin-cli`, and
every Devin session and span id changes prefix with it, so stored findings or
cursors keyed on the old ids read as new sessions. A kind filter naming
`devin-cli` matches nothing; there is no alias. Claude Code is unchanged.

**Additive otherwise.** A Devin call that carried `tool_class` `None` may now
carry a class; no field, status or span derivation changed.

Beta, and no back-compatibility guarantee before 1.0. Supported hosts are
macOS and Linux.
