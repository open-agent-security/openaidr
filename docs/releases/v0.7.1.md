# 0.7.1 — a plugin's MCP server joins its log

Claude Code names an MCP server from a plugin in two ways. A tool name in the
transcript has `plugin_<plugin>_<server>`. The connection log directory has
`mcp-logs-plugin-<plugin>-<server>`, with hyphens in place of underscores.
The reader did not join the two names. Thus a call to a plugin's server did
not get its transport, outcome or duration, and its session fell to
`count_mismatch`.

## Highlights

- **A call to a plugin's MCP server gets its log data.** The reader now maps
  the transcript name of a plugin server to the spelling of its log directory.
  Thus the call gets its transport, status and duration from the connection
  log, the same as a call to any other MCP server. The displayed server name
  does not change. Servers that are not from a plugin do not change.

## Install

`uv tool install openaidr==0.7.1` or `pip install openaidr==0.7.1`.

## Compatibility

Beta, no back-compat guarantee before 1.0.

- **Claude Code sessions that use a plugin's MCP server.** A call that 0.7.0
  left without a transport, outcome or duration can now have them. Its session
  can change from `count_mismatch` to `applied`.
- No span derivation, kind, class or model field changed. `adr-sensor` is
  unchanged.
