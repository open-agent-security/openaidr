# 0.2.0 — a turn carries the time of its own record

The session model gains two fields, and consumers can date what they find.

## Highlights

- **`Turn.occurred_at`** — when the record that produced the turn was written,
  as an instant in UTC. Every transcript record carries a timestamp and this
  package already read them: `_recorded` filed both ends of a call under
  `started`/`ended`, `_duration` subtracted the pair, and both absolute instants
  were discarded. `Session.started_at` — the *earliest* record — was the only
  absolute time to survive, so the finest clock a consumer could reach was the
  moment a session began. For a session running for days, or resumed across
  weeks, that is wrong by the whole span.

- **`Session.last_activity_at`** — the newest record observed for the session.
  **Not an end**: sessions are read while still being written, so this is the
  latest activity seen and says nothing about whether more is coming. **Not the
  newest turn either**: boundary and tool-result records carry timestamps
  without producing turns, so this is routinely later than the last
  `occurred_at`, which is what makes it the recency signal a consumer ordering
  sessions needs.

- **`ToolCall` deliberately gains nothing.** A call's start is written from its
  own record's timestamp, which is its turn's `occurred_at` by construction, and
  — where `duration_ms` is the transcript's own round trip rather than one the
  MCP connection log filled in — its end follows from that and the duration
  already published. Carrying either again would restate a value the model
  already holds. See ADR-0010.

## Compatibility

Additive and defaulted. Both fields are `datetime | None = None`, so anything
constructing a `Session` or a `Turn` positionally is unaffected, and a consumer
that does not read them sees no change.

**Durations are byte-identical to 0.1.1.** The turn's time is joined on
`(session, uuid, occurrence)` — the key `permission_mode` and `cwd_at` already
use — so this change never enters the bare-call-id join that forces
`started`/`ended` to be withheld for a withheld or reused call. `_duration`,
`_tool_calls` and those guards are untouched, and a test asserts the published
durations do not move.

## Timezones

`_timestamp` now resolves every value to an instant in UTC, applying the same
rule the parsing dependency applies to the session start: an offset-bearing
value is converted, and a value carrying no offset is taken as UTC. One rule
across the model, so its two time fields cannot resolve a zone differently.

An absent or unparseable timestamp stays absent. The line not crossed is
inventing a value the transcript never stated — no collection time, no
neighbouring turn's value, no file modification time.

**`Session.started_at` is held to that line too, which changes it.** The start is
now the oldest record this package read for the session, recovered in the same
pass as the two new fields, rather than the value the parsing dependency
produces — which substitutes `datetime.now()` where a session's records state no
time it can read, dating a months-old transcript to the moment it was collected.
For every session whose records carry a readable time, and that is every Claude
Code transcript observed, the value is unchanged. For one whose records do not,
`started_at` is now `None` where 0.1.1 returned the collection time.

## Decisions

- [ADR-0010](../adrs/0010-a-turn-carries-the-time-of-its-own-record.md) — a turn
  carries the time of its own record; a call carries none. Records the rejected
  alternatives: per-call timestamps, a modelled turn end, a session end,
  interpolating an undated turn, and applying a stricter zone rule than the
  dependency's.
