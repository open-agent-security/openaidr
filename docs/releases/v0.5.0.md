# 0.5.0 — a second agent kind: Devin CLI

A second agent kind is read: `devin-cli`, through an OpenAIDR-owned reader of
Devin's own store and run logs. With two kinds, the same act has two names, so
every tool call now also says what the tool is, and carries its most-used
arguments under one key name. `docs/specs/devin-cli.md` is the design.

## Highlights

- **Devin CLI sessions are read** (ADR-0018 to ADR-0020). `devin-cli` covers
  Devin CLI, Devin Local, and editors driving it over ACP. Devin Cloud and
  Cascade are not covered.
  - The reader opens `sessions.db` read-only, in one read transaction per pass,
    and follows it as it grows by re-emitting every session whose output
    changed. It never runs the agent's binary.
  - Turns come from the current conversation (`main_chain_id`). Responses and
    their tokens come from the whole tree, regenerations included, one per
    `request_id`. Sub-agents are `devin-cli:<session>:<agent_id>`, by ADR-0001's
    existing rule.
  - MCP connections, the build and the entrypoint come from the process's run
    log, joined through the session's lock. When two sessions share one
    process, their connections can't be told apart, so they are withheld as
    `placement_ambiguous` and the build and entrypoint are kept.
  - The data root is `$XDG_DATA_HOME/devin/cli`, else `~/.local/share/devin/cli`.
    `OPENAIDR_DEVIN_ROOT` overrides it for the CLI, and `default_readers(devin_root=…)`
    does the same for callers.
  - Known gaps: call durations, per-turn permission mode, and MCP server
    identity. The run-log parser and lock join were validated against a live
    run. The store side was tested against synthetic stores built from the
    binary's schema and three open-source parsers, not a signed-in session.
- **`ToolCall.tool_class` and `ToolCall.canonical_arguments`** (ADR-0021).
  - The class comes from a closed vocabulary: `shell`, `file_read`,
    `file_write`, `file_edit`, `web_fetch`, `delegate`, `mcp` and others,
    filled from per-kind tables.
  - Canonical arguments use keys such as `command`, `path` and `url`, under
    one name across kinds. Canonical arguments are local-only, like `arguments`.
  - A tool name a table doesn't know gets no class, never `other`, and a key
    the call didn't record is absent. `tool_name` and `arguments` are unchanged.
- **`ToolCall.exit_code`**: a shell command's own exit status, where the kind
  records one. Devin CLI does; Claude Code does not.
- **Context items name their parts** (ADR-0016). `ContextItem.parts` holds each
  skill of a skill listing and each server of an MCP instructions record, but
  only where the record pairs every part with its name for certain. Otherwise
  it is empty.
- **`ContextItem.occurred_at`** is when the record was written (ADR-0017). It is
  a lower bound on when the item started reaching the model. It does not show
  that the item is still active: a later removal is never recorded.
- **`Session.compactions_recorded` and `Session.subagents_recorded`**
  (ADR-0022). Each says whether the kind records that list at all, so an empty
  list can be read as "none happened", not as "the kind cannot say".
- **Two new `MCPConnection.failure_category` values**: `spawn` (the server
  process could not be launched) and `policy` (an organisation or client policy
  refused the server).

## Install

`uv tool install openaidr==0.5.0` or `pip install openaidr==0.5.0`.

## Compatibility

**Additive for the model.** Every new field is defaulted and comes after each
existing field on `ToolCall`, `ContextItem` and `Session`. Positional
constructors keep working. Span identity, turn identity and every existing
field are unchanged for `claude-code`. `render_json` gains each call's
`tool_class` and `exit_code`.

- **`default_readers()` and `default_incremental_readers()` now return a Devin
  reader too.** `root=` still names only Claude Code's root. Devin's data root
  is read from its default location unless `devin_root=` is passed.
  - A caller that passed a test or fixture root now also gets that machine's
    real Devin sessions.
  - A consumer that assumed every session is `claude-code` will see `devin-cli`
    sessions.
- **Replace a `devin-cli` session's turns wholesale; never append.**
  Regenerating a turn in Devin moves the current conversation to another
  branch, so turns can disappear between reads (ADR-0019). Spans are never
  reused. A session deleted from Devin's store is not announced.
- **New values in closed vocabularies.** A consumer that handles every case
  needs new ones for:
  - `mcp_log_state` gains `placement_ambiguous`.
  - `failure_category` gains `spawn` and `policy`.
  - `Compaction.trigger` can be `unknown`, for a kind that records a compaction
    but not its cause (Devin CLI).

Beta, and no back-compatibility guarantee before 1.0. Supported hosts are
macOS and Linux.
