# 0.5.1 — every kind's sessions, without learning its layout

A long-lived consumer could follow a growing session once it named the file,
but had to know each kind's layout to name it, and a Claude Code built-in
newer than the tool table arrived unclassed. This release closes both.

## Highlights

- **Each reader says where its session files live** (ADR-0023).
  `IncrementalCollector.locations()` returns, per kind, the directories to
  watch: Claude Code's projects root, Devin CLI's data root. Hand any file that
  changed beneath them to `collect(kind, path)`; a file the kind does not read
  is ignored, and a sub-agent's file returns the sub-agent's session. OpenAIDR
  still watches nothing itself. `IncrementalCollector` also takes `devin_root=`
  beside `root=`.
- **Twelve more Claude Code built-ins are classed** (ADR-0021), each seen in a
  real transcript. `Monitor` is `shell`, with its `command` as a canonical
  argument. `TaskOutput`, `TaskStop`, `TaskCreate`, `ToolSearch`,
  `EnterPlanMode`, `SendMessage`, `ListAgents`, `SubagentHandback`, `Artifact`,
  `ReportFindings` and `SendUserFile` are `other`. Before, each was `None`.

## Install

`uv tool install openaidr==0.5.1` or `pip install openaidr==0.5.1`.

## Compatibility

**Additive for the model.** No field, span or status changed. A call to one of
the twelve tools above now carries a `tool_class` where it carried `None`, and
a `Monitor` call carries `canonical_arguments["command"]`.

- **`IncrementalReader` gains `locations()`.** A third-party reader passed to
  `IncrementalCollector(readers=...)` must implement it.
- **`devin_root` on `IncrementalCollector` is keyword-only**, so the existing
  positional `root, readers` order is unchanged.

Beta, and no back-compatibility guarantee before 1.0. Supported hosts are
macOS and Linux.
