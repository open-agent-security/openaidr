# 0.12.0 — Each tool's own description, as context

OpenAIDR now carries the description of each tool that reached the model. A
consumer can join a description to a call by the tool's name. This release
reads the descriptions for Claude Code and Codex.

## Highlights

- **Tool descriptions are context.** A new context source, `tool_listing`,
  holds the description of each tool that the model can call. Each record that
  lists tools gives one context item. Each tool is one part, with the tool's
  name and its description. The part's name comes from the rule that names a
  call to that tool, so a consumer joins a description to a call by name. A
  session lists each name and description once. New words for a tool give a new
  part, because the model reads the new words from then on (ADR-0047). The text
  is local-only, as for the other context items.
- **Claude Code.** The reader reads the `prompt_snapshot` attachment, which
  lists the tools loaded at the start. It also reads the `deferred_tools_record`
  attachment, which lists the tools that a tool search loaded. The result of the
  tool search holds no description. `docs/specs/session-collection.md` gives the
  rule.
- **Codex.** The reader reads each tool with a description in a
  `tool_search_output` record. The `mcp_instructions` item from the same record
  does not change. `docs/specs/codex.md` gives the rule.

## Install

`uv tool install openaidr==0.12.0` or `pip install openaidr==0.12.0`.

## Compatibility

Beta, no back-compat guarantee before 1.0.

- **Span identity does not change.** A tool listing has its own span key,
  `context.tools`. In Claude Code, listings are counted apart from the other
  context items, so no other context span moves. In Codex, the index is the
  line of the record, as for the other context items.
- **A new context source.** `ContextItem.source` can now be `tool_listing`. A
  consumer with a closed list of sources must add it. The fields of the session
  model do not change.
- **Codex names more calls by their configured server and raw tool name.**
  Codex shows the model a sanitised name. A completed `McpToolCall` item records
  the configured server and the raw tool name. Before this release, a call with
  no completed item of its own kept the sanitised name. Now the reader takes the
  names from the other completed calls of the session, by the rules in
  `docs/specs/codex.md#tool-names`. For example, a call to `search_items` in
  `mcp__my_server` with no completed item was `my_server` and `search_items`. If
  another call to that tool completed as `my-server` and `search.items`, the
  call is now `my-server` and `search.items`. A call with its own completed item
  does not change. A consumer that stored `mcp_server` or `tool_name` for such a
  call can see a new value when it reads the session again. The span of the call
  does not change.
- **Dependencies are unchanged.**
